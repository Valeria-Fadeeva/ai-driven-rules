# Протокол POSIX для манипулирования потоками и редактирования файлов с сохранением контекста

## 1. Обоснование и оптимизация контекста
Для устранения раздувания контекста, предотвращения исчерпания токенов и смягчения эффекта галлюцинаций LLM во время масштабных переписываний блоков, Агенту строго ЗАПРЕЩЕНО использовать полные блоки `SEARCH/REPLACE` или выгружать все содержимое файлов для незначительных корректировок.
Вместо этого Агент ДОЛЖЕН использовать собственные утилиты Linux POSIX (`sed`, `grep`, `awk`, `head`, `tail`) для выполнения атомарных, точных изменений непосредственно в файловой системе.

---

## 2. Отмена устаревших ограничений
* **Перенаправления `echo` и EOF:** Разрешены ТОЛЬКО при инициализации полностью пустых файлов или добавлении неструктурированных линейных векторов (например, при записи необработанных конфигураций среды или добавлении одной строки). Использование `cat << 'EOF'` для перезаписи многострочных блоков исходного кода УСТАРЕЛО.

* **Внедрение `python3 -c`:** Разрешено ТОЛЬКО в качестве резервного варианта при обработке вложенных многострочных шаблонов регулярных выражений, где стандартный синтаксис экранирования `sed` ограничивает логику выполнения.

---

## 3. Строгие директивы выполнения для потоковых утилит

### 3.1. Операции чтения (проверка с помощью `sed`, `grep`, `head`)
Перед изменением любого блока агент ДОЛЖЕН разрезать контекст файла, чтобы извлечь только соответствующую целевую область времени выполнения.

* **Извлечение целевой строки:** Используйте `sed -n 'X,Yp' filename` для вывода точных границ блока. Выгрузка более 100 строк нетронутого кода в историю командной строки является нарушением контекстной экономики.

* **Обнаружение шаблонов:** Используйте `grep -n "pattern" filename` для получения точных номеров строк структуры перед внедрением структурных патчей.

### 3.2. Операции записи (хирургическое редактирование на месте с помощью `sed`)
При применении технической спецификации или исправлении ошибки компиляции агент ДОЛЖЕН создавать атомарные, тестируемые команды изменения потока:

* **Подстановка строк (на месте):**

``bash

sed -i 's|exact_target_match|replacement_string|g' filename

```
*Правило:* Всегда используйте вертикальные черты `|` или альтернативные разделители, если целевая строка содержит стандартные косые черты каталогов `/`, чтобы предотвратить нарушение управляющей последовательности.


* **Добавление строк (вставка ПОСЛЕ совпадения):**

``bash

sed -i '/marker_pattern/a \ new_code_line_to_append' filename
```

* **Вставка строк (вставка ДО совпадения):**

``bash
sed -i '/marker_pattern/i \ new_code_line_to_insert' filename
```

* **Удаление целевого блока:**

``bash
sed -i 'X,Yd' filename
```
*Правило:* Диапазоны строк `X,Y` ДОЛЖНЫ быть проверены с помощью предварительного выполнения команды `grep -n` непосредственно перед циклом удаления, чтобы убедиться, что смещения файла не сместились.

## 4. Цикл проверки и валидации
Сразу после выполнения любого цикла `sed` или цикла модификации потока, Агент ДОЛЖЕН проверить синтаксис файла и согласованность системы:
1. Проверить точную измененную зону с помощью `sed -n 'X,Yp' filename`.

2. Запустить локальные обработчики компилятора/линтера (например, `cargo check` для Rust, `flutter analyze` для Dart/Flutter или `bash -n` для скриптов оболочки).

3. Если состояние синтаксиса недопустимо, Агент ДОЛЖЕН автоматически отменить изменения с помощью Git или операций отмены, уточнить регулярное выражение и выполнить операцию повторно.
