# GIT И ДОКУМЕНТИРОВАНИЕ ИНФРАСТРУКТУРЫ

## 📑 1. ПРАВИЛА GIT И АВТО-ДОКУМЕНТИРОВАНИЕ
- **Фиксация изменений:** После завершения логического этапа или закрытия атомарной подзадачи фиксируйте изменения в Git. Категорически запрещено накапливать огромные пулы разнородных правок в один коммит.
- **Предварительный аудит:** Перед формированием коммита модель обязана выполнить команды `git status` и `git diff`, чтобы убедиться в отсутствии лишних проиндексированных файлов (логов, локальных БД, дампов сессий).
- **Спецификация сообщений:** Сообщение коммита должно строго соответствовать стандарту Conventional Commits (`feat:`, `fix:`, `chore:`, `refactor:`, `test:`, `build:`) на английском или русском языке в нижнем регистре.
  - *Пример:* `feat(detector): add auto-detection of luks2 swap partitions`
- **Запрет на слепой коммит:** Запрещено использовать команду `git add .`. Индексация файлов должна производиться точечно (указывая конкретные целевые файлы), чтобы избежать засорения репозитория.
- **Блокировка коммита:** Категорически запрещено делать коммит, если компиляция проекта завершается ошибкой или завалены локальные системные тесты.

## 📝 2. ОБЯЗАТЕЛЬНАЯ СИСТЕМНАЯ ДОКУМЕНТАЦИЯ
- **Синхронизация с TODO.md:** Ведите непрерывную документацию по текущему проекту в локальном файле `TODO.md` (в корне репозитория или конкретного проекта): фиксируйте, что необходимо сделать, что реализовано иначе, какие проблемы обнаружены и какие задачи отложены.
- **Критические узлы:** Обязательно фиксируйте в документации и README ключевые нюансы и скрытые системные требования, без знания которых компиляция или запуск программы в ОС Linux будут невозможны.
- **Инструменты и утилиты:** Каждый новый создаваемый системный инструмент, скрипт автоматизации или фоновый демон обязан иметь собственный файл документации в формате Markdown по пути текущего проекта: `docs/tools/<tool_name>.md`. Документация должна включать: Назначение, Архитектуру взаимодействия, Спецификацию API, Примеры вызова/конфигурации и Известные ограничения. Этот файл создается сразу после реализации инструмента, строго ДО вызова команды коммита.
- **Самодокументируемый код:** Пишите чистый, самодокументируемый код с соблюдением канонов форматирования целевого языка программирования (Rust/Dart/Python).
- **Актуализация README:** Обновляйте файлы `README.md` и `README.ru.md` проекта по мере расширения его архитектуры или изменения логики деплоя/сборки. Файл `README.md` должен быть составлен на английском языке, файл `README.ru.md` — на русском. Обязательно создавайте между ними перекрестные навигационные ссылки в самом начале документов.
- **LICENSE (Лицензирование):** Лицензия разрабатываемого программного обеспечения во всех репозиториях экосистемы всегда строго **AGPL-3.0-only**. Модель обязана следить за чистотой копирайтов и наличием лицензионных блоков в коде.
- **RUST Edition (Спецификация компилятора):** Версия языка Rust во всех бэкенд-компонентах и демонах всегда жестко зафиксирована на **Edition 2024**, используемый rust toolchain — исключительно **stable**. Категорически запрещено использовать устаревший синтаксис или экспериментальные ночные (nightly) фичи.
